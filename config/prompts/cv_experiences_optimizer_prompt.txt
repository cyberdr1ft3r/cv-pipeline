## OBJECTIF PRINCIPAL :
Réécrire chaque expérience pour qu'un recruteur voit IMMÉDIATEMENT que le candidat a DÉJÀ accompli les responsabilités et utilisé les technologies demandées dans l'offre.

## STRATÉGIE D'ALIGNEMENT PARFAIT :

### 1. ANALYSE DE L'OFFRE (faire mentalement)
- Technologies OBLIGATOIRES : Identifier toutes les technologies mentionnées
- Responsabilités CLÉS : Identifier les tâches principales du poste
- Soft skills : Identifier les compétences comportementales (leadership, agilité, etc.)
- Mots-clés récurrents : Noter le vocabulaire utilisé

### 2. TRANSFORMATION DES MISSIONS
Pour CHAQUE mission, appliquer cette formule :
**[Verbe d'action] + [Technologie de l'offre] + [Contexte/Résultat]**

Exemples de transformation :
- AVANT : "Développement d'applications web"
- APRÈS : "Développé des APIs REST avec Spring Boot et déployé sur Kubernetes en environnement production"

- AVANT : "Maintenance du code"
- APRÈS : "Optimisé les performances applicatives via refactoring et mise en place de tests unitaires (JUnit, 85% coverage)"

### 3. ENRICHISSEMENT STRATÉGIQUE DES MISSIONS
Ajouter les aspects de l'offre non explicitement mentionnés mais COHÉRENTS avec le poste :

| Si le poste implique... | Ajouter des missions sur... |
|------------------------|----------------------------|
| Backend Java | Spring Boot, Microservices, API REST, JPA/Hibernate |
| Frontend | Angular/React, TypeScript, responsive design |
| DevOps | Docker, Kubernetes, CI/CD (Jenkins/GitLab), monitoring |
| Cloud | AWS/Azure/GCP, déploiement, scalabilité |
| Architecture | Conception technique, choix d'architecture, documentation |
| Leadership | Mentorat, revue de code, coordination équipe |
| Agilité | Scrum, Sprint planning, rétrospectives, collaboration PO |

### 4. FORMAT STRICT DES MISSIONS
- Maximum 5 missions par expérience
- 10 à 20 mots par mission
- Commencer OBLIGATOIREMENT par un verbe au passé composé :
  - Développé, Conçu, Implémenté, Architecturé, Optimisé, Déployé
  - Géré, Dirigé, Coordonné, Formé, Accompagné
  - Automatisé, Migré, Intégré, Refactorisé, Sécurisé
- Inclure des métriques quand possible (%, réduction, amélioration)

### 5. CONTEXTE OPTIMISÉ
- 1 phrase de 15-25 mots
- Mentionner le secteur/domaine et l'enjeu business
- Utiliser le vocabulaire de l'offre
- Exemple : "Développement d'une plateforme e-commerce haute disponibilité en architecture microservices pour un leader du retail"

### 6. ENVIRONNEMENT TECHNIQUE
- Inclure TOUTES les technologies pertinentes de l'offre si cohérentes
- Ajouter les technologies complémentaires logiques (Git, Docker, tests, etc.)
- Ordonner par pertinence pour l'offre

### 7. SCORING DE PERTINENCE
- 90-100 : L'expérience correspond directement au poste (mêmes technos, mêmes responsabilités)
- 70-89 : L'expérience est dans le même domaine technique
- 50-69 : L'expérience est transférable avec enrichissement
- Ordonner les expériences par relevance_score décroissant

## RÈGLES IMPORTANTES :
- ✅ Reformuler avec le vocabulaire EXACT de l'offre
- ✅ Enrichir avec des technologies cohérentes
- ✅ Ajouter des métriques et résultats
- ✅ Valoriser le leadership et la collaboration si demandés
- ❌ Ne PAS inventer une expérience totalement différente
- ❌ Ne PAS ajouter de technologies incohérentes avec le niveau/rôle
